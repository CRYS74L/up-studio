# 移动端录屏审查与优化（2026-09-28）

## 审查范围

完整覆盖用户提供的 49.8 秒主屏幕 Web App 录屏，按连续时间顺序逐段审查，关键返回动画另以 30 fps 展开检查。桌面上的 WebKit 26.5 和 Chromium 移动视口用于验证代码行为，不代替 iPhone 的系统手势、120 Hz 合成器和温度测量。

| 录屏区间 | 观察 | 本次处理 |
| --- | --- | --- |
| 1.7–6.2 s | 启动白屏、字体及数据占位持续较久 | 原字体常用字分包、完整字符兜底；减少封面预热；静态资源及 JSON gzip；哈希资源长期缓存 |
| 8.8–20.8 s | 图表滚动时详情频繁出现并停留 | 触控改为点按显示详情，滚动撤销详情并抑制本次滑动结束后的误触发 |
| 滚动各段 | Dock 背景更新滞后、采样位置不稳定 | 去除普通事件后的 800ms 连续重绘；同步视觉视口；更新图表/文本/选择状态而非反复克隆整页 |
| 21–23 s | 设置页还在读取时呈现灰色控件 | 设置预取不再串行等待稿件和封面；局域网设备的只读限制仍保留 |
| 27.8–28.3 s | 返回已看过的分析图表后，曲线再次从空白绘制 | 命中图表快照后不重复播放首次进入动画，后续数值变化动画保留 |
| 44.2–44.8 s | iOS 返回手势中整页及 Dock 一起退场后出现空白 | 浏览器历史返回与站内点击分离，不再叠加网站滑动动画；即时恢复历史滚动位置 |
| 全程 | Dock 离底部较远；部分触控入口较小 | 去除额外底部叠加留白；在安全区 34px 的设备上 Dock 留白由 46px 调整为 22px；扩大菜单与账号控件的触控高度 |

## 视觉约束

液态玻璃的折射、模糊、饱和度和透明度参数保持不变。字体使用原有文件及字重，常用字包校验字宽；两类 unicode-range 合并后的字符集合与完整字体完全一致。未知字符仍能加载原完整字体。没有用系统字体替换、删掉玻璃或降低图表质量来换速度。

Apple HIG 要求浮动栏与安全区域协调，但未给出适用于自定义网页的固定 CSS 底边距。本次以用户 App Store 截图作为视觉参考，用 `max(8px, safe-area-inset-bottom - 12px)` 适配不同安全区。参考：[Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)、[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

## 验证与边界

- 同条件 Chromium 移动视口：首屏字体资源约 26.47MB → 7.76MB，首屏封面请求 34 → 8。
- 静止显示图表详情 6 秒：动画帧调度约 397 → 0，主线程任务约 179ms → 5ms。此数值是一次受控浏览器测量，不是手机耗电或温度数据。
- 稿件 API 响应约 538KB → 61KB，gzip 解压内容一致；流式响应不进行缓冲压缩。
- WebKit：玻璃几何检查误差 0；历史返回恢复到原 200px 滚动位置，残留快照为 0；无页面脚本错误。
- Chromium 触控：点按能打开详情，纵向滑动能滚动页面并关闭详情。
- 字体分包、时间标签、绘制状态同步、动画及既有数据逻辑的自动测试通过。
- 仍需同一台 iPhone 复测发热、系统侧滑返回、惯性滚动及主屏幕安全区；不能从桌面引擎验证推断这些问题已在所有 iPhone 上完全消失。
